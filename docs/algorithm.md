# 同见：透明内容排序（v1）

本文档描述当前真正运行的排序算法，与代码 `src/ranking.js` 保持单一事实来源。规则、参数、输入与数据边界全部公开、可复算；`/algorithm` 页从本模块直接渲染，避免"描述的不是真实代码"。

## 核心设计意图

排序是**发现工具**（先让你看到什么），不是"这内容有多好"的**价值判定**。它刻意：

- 用"价值"而非"认同"作质量信号：避免"人人同意的共识内容"被捧高，保护创新性、非主流的观点。
- 让**讨论深度**成为高权重的价值来源（wDiscussion > wValue），奖励"真正的来回探讨"而非"刷票"。
- 给时间衰减加**软下限**，让"经久不衰"的好内容不被时间清零。
- 提供**确定性、公开、限时的复活机制**，对抗"强者恒强"的马太效应，给埋没的好内容第二次被发现的机会。

## 价值分 value

```
value = wValue · (价值投票的 Beta 样本校正均值 × 参与度增益) + wDiscussion · 讨论深度
```

### 三档"收获"价值投票（Beta 样本校正）

投票为三档：高(=1)、中(=0.5)、低(=0)，用 Beta 先验(α=β=1)做样本校正：

```js
valueScore = (Σ 分数 + α) / (票数 + α + β)
```

低样本会被拉向中性(0.5)，避免"少数人全高分"或"少数人全低分"窜顶；票数为 0 时该信号为 0。

参与度增益：

```js
participationMultiplier = min(1, 票数 / valueParticipationFull)
```

票数不足时抑制价值信号，防止"一票定音"。

### 讨论深度

奖励"来回探讨"，而非纯回复条数：

```js
depth = min(discussionCap, 主题数×讨论主题权重 + 直接回复数×回复权重 + 深层(≥2)回复数×深层权重)
```

深层回复（回复的回复）权重虽低于主题，但代表真正的交互深度。

## 时间衰减

```
hot        = value / (min(age小时, ageCap天×24) + 2)^gravity
evergreen  = value / (min(age天, 730) + 1)^evergreenGravity
```

- hot 有**软下限**：超过 `ageCapDays` 后不再衰减，好而旧的内容不会归零，但 30 天内仍会流转。
- evergreen（典范页）几乎不衰减，是"经久不衰"内容的归宿；与 hot 分开，避免好内容长期占用首页有限位置。

## 复活机制

```
每 revivalEveryHours 小时一个周期，选 revivalSlots 个
选择分 = ln(时长分钟) × revivalDurationWeight + hash(videoId + cycle)
资格：value ≥ revivalMinValue 且 revivalMinDaysOld ≤ 年龄 ≤ revivalMaxDaysOld
加成：选中后 revivalBoostHours 小时内 hot 分 × revivalBoostFactor
限制：每周期每作者最多 revivalAuthorCap 个
```

- 选择用 `hash(videoId, cycle)` 而非真随机——确定性、公开、任何人可复算本周期谁会被复活，且不可操控。
- 时长取对数做**创作成本权重**：高成本（长）内容多一次被发现机会，但先有质量门槛，长视频不会凌驾质量。
- 限时加成，避免被复活的内容长期霸榜。

## 使用的数据

1. 该视频的三档价值投票计数（高 / 中 / 低）
2. 该视频的讨论结构（顶层主题数、直接回复数、深层回复数）
3. 视频发布后的年龄（小时）
4. 视频时长（仅用于复活机制的创作成本权重）
5. 视频作者（仅用于复活机制的作者名额上限）

## 不使用（数据边界）

- 用户身份 / 账号信息
- 观看历史或观看序列
- 任何服务端用户画像、兴趣推断或人口属性
- 浏览次数 / 播放量（当前未采集，也不用于排序）
- 点赞之外的任何货币化或推广信号

## 参数

全部参数见 `src/ranking.js` 的 `RANKING_PARAMS`（版本 `RANKING_VERSION`）。关键项可在 `/algorithm` 页查看。

## 个性化与透明

- 当前没有个性化推荐；排序是公开的全局排序。
- 若未来加入个性化，按架构文档既定路线采用"本地优先"：服务端返回公开候选集，浏览器按用户主动关注/屏蔽的标签本地重排；账号只同步用户主动的信号，绝不存服务端观看序列/画像。这一层会显式标注、可关，且不污染全局排序的透明性。
- 任何参数/公式变更都要走"版本 → 离线校验 → 公开说明 → 上线 → 可回滚"的链路。

## 离线校验

`scripts/validate-ranking.js` 用合成的候选目录跑排序并断言不变量：单作者不霸榜、低价值死内容掉出、新而好的内容能浮上来、老而好内容在典范页有归宿、复活确定且作者受限、衰减有下限。机制可离线验证；"高/中/低"是否真是好的价值信号，留待真实互动数据校准。
