# 同见平台架构与维护边界

本文记录已经落地的产品约束和数据边界，避免管理后台、排序或推荐能力破坏现有语义。当前仍是实验性 MVP，但已包含 CMS V1 的本地治理闭环；它提供举报、案件、审核、申诉和审计能力，不等于已经具备公开运营所需的完整法务、安全和事件响应体系。CMS 的精确事务与权限设计见 [`cms-technical-design.md`](cms-technical-design.md)，概念导读见 [`cms-learning-guide.md`](cms-learning-guide.md)。

## 长视频产品约束

- 同见始终以横屏、长视频为主要内容形态，不设计竖屏短视频的沉浸式连续滑动信息流。
- 首页卡片、播放器和封面统一使用 16:9 展示区域；非 16:9 视频在播放器中保持原比例，不裁切原始画面。
- 自定义封面必须严格为 16:9，尺寸在 1280×720 至 3840×2160 之间，只接受 JPEG、PNG 或 WebP，且不得超过 5 MiB。服务端必须真实解码、去除元数据并规范化为 WebP，不得只信任文件头。
- 没有自定义封面时，独立验证器在完整媒体验证通过后读取第一帧，按比例缩放并补边为 1280×720 JPEG。封面提取不是视频转码，不改变原媒体。

## 页面与发现

- `/` 和 `/search`：公开视频目录与搜索。
- `/categories`、`/categories/:slug`：平台维护的多级分类。
- `/tags`、`/tags/:slug`：发布者添加的标签。
- `/videos/:id`：播放、作品信息、双向评价和树状讨论。
- `/account/reports`、`/account/appeals`：成员查看本人举报、相关审核决定和申诉。
- `/cms`、`/cms/*`：审核员和管理员使用的独立治理工作区；进入前需要当前会话完成密码再认证。
- `/about`：平台宗旨与实验边界。
- `/algorithm`：当前实际运行的排序、使用的数据和未使用的数据。

当前搜索匹配标题、创作者署名、作品描述和标签。数据量仍很小时使用参数化 SQLite 查询；需要扩展到全文索引时，应保持相同的公开查询语义并增加迁移，而不是改变 URL。

## 技术状态与内容管理状态必须分离

`videos.validation_status` 只描述媒体管线状态：等待、验证中、通过、有警告、内容拒绝或验证服务失败。验证器只能修改这组状态以及探测结果、摘要和自动封面。`validation_started_at` 同时作为可续租的任务版本；自动封面、完成、拒绝和失败写入都做版本 CAS，因失联而被重领的旧 worker 无权提交结果或安排文件删除。

CMS V1 使用的内容与账号状态是：

- `videos.visibility`：`public`、`unlisted`、`private`。
- `videos.moderation_status`：`visible`、`hidden`、`removed`。
- `discussions.moderation_status`：`visible`、`hidden`、`removed`；与作者主动删除的 `deleted_at` 分离。
- `users.role`：`member`、`moderator`、`administrator`。
- `users.status`：`active`、`suspended`、`disabled`。
- `categories.is_active`、父分类与排序字段由管理能力维护。

CMS 不把“审核隐藏”伪装成“媒体损坏”，也不允许管理页面直接把未通过验证的媒体标记为可播放。视频、讨论和账号分别使用 `moderation_version` 或 `governance_version` 防止并发覆盖，分类、标签和删除队列任务用 `updated_at` 作比较令牌；验证重试同时比较失败状态和验证开始/完成双时间戳，防止状态经历重试循环后的 ABA 覆盖。后台写操作经固定权限、密码再认证和领域命令，在单个事务内重新检查操作者与目标、更新必要事实并追加审计。密码再认证尝试同时按工作人员账号和来源 IP 冷却，且成功时只能更新属于当前操作者的当前会话。只有实际改变内容或账号治理状态的决定才同时追加 `moderation_actions` 和作者通知；仅有角色字段不构成后台权限。

分类使用稳定 slug 作为公开 URL，显示名称可以由 CMS 修改，当前最多两级。视频选择一个主分类；标签使用多对多关系，单个视频最多 8 个。标签允许发布者创建并在写入前规范化、去重；管理员可以改显示名、停用或合并标签，但不改 slug。合并后的旧 slug 重定向至目标标签，既有视频关联去重保留。

## 治理案件、决定与申诉

成员举报或工作人员主动调查都会形成 `moderation_cases`。案件恰好指向一个视频或一条讨论，按 `open → in_review → resolved` 处理；结案结果是确认违规或无违规。未分配的 `open` 案件认领后才有一名当前负责人；只有该人能追加带案件版本 CAS 的内部备注、审核目标、授权私密媒体或结案。管理员可以介入转交，但不能跳过认领直接执行这些案内动作。任何工作人员都不能为自己的内容建立主动调查、认领或处理案件，也不能把案件转给目标作者；只要曾举报某视频或讨论，就不能借另一案件读取、认领、转交、审核或复核同一目标，也不能被选为负责人。举报人只看到状态、结果和公开说明，不看到内部备注、工作人员身份或敏感证据。

举报分类固定为垃圾/欺诈、骚扰或仇恨、违法或危险、隐私或版权、冒名或误导性元数据、其他，说明为 20–2000 字。同一成员不能举报自己的内容或自己无权访问的对象，对同一目标最多存在一个未结案件。举报冷却同时按登录账号和来源 IP 计算，状态只在单进程内存中保留。审核政策处理行为、权利侵害和明确平台规则，不把普通观点分歧或内容质量当作移除理由。

视频、讨论和账号决定追加到 `moderation_actions`，保存公开说明、内部备注、治理前后快照和版本。受影响成员在 `/account/appeals` 看到涉及本人的完整决定与最多 2,000 字公开理由；既有系统通知只保存前 1,000 个 Unicode 字符作为预览。V1 只允许在期限内对视频/讨论隐藏或移除、账号暂停提交一次申诉。申诉按 `pending → in_review → resolved` 处理：先由非原操作者优先认领，再由当前复核人提交结果；当前复核人或管理员可以把它转给另一名合格、独立的复核人，申诉人和任何同目标举报人都不能复核，举报过账号目标作者内容的管理员也不能复核该账号决定。视频和讨论申诉可由审核员或管理员查看与复核，账号暂停申诉只能由管理员查看与复核。撤销决定仍以原动作版本做 CAS，若其后已有新决定则保留 `in_review` 并标记冲突，不自动覆盖。人工解决时只有当前复核人能以申诉/目标双重 CAS，显式选择恢复原动作前状态或保留当前后续状态。

`audit_events` 记录所有 CMS 写操作、角色变化、任务重试、密码再认证和敏感媒体授权。审计是只追加记录，后台没有删除入口；治理前后 JSON 只包含必要状态，不保存密码散列、Cookie、CSRF、完整媒体或无关个人资料。管理员看到的是除本人利益冲突对象外的全量视图：查询固定排除关联当前管理员作为内容作者、申诉人或账号目标的案件、视频、讨论、申诉和账号事件，不能用筛选条件绕过；底层事件仍完整保留。

工作人员角色与其成员身份同时存在。本人创作的内容、本人视频所承载的讨论、本人申诉、本人账号和曾由该工作人员举报的目标都从案件、内容、账号、申诉、近期动作与审计视图中统一隔离；举报过某作者内容的管理员也不能进入或治理该作者账号。相关详情按不可见处理，筛选条件不能绕过；讨论上下文仍保留树结构，但冲突节点的正文、作者、状态和链接会被遮蔽。这样既防止自我治理和举报人转任工作人员后借另一案件处理同目标，也避免从内部操作者字段反推出受保护身份或证据。

私密、未列出、作者撤回或治理隐藏/移除的视频在 CMS 列表中只显示必要元数据和占位封面。工作人员必须从由自己负责的 `in_review` 案件申请短时、会话绑定的访问授权，或先填写理由建立主动调查案件再认领；申请还要用案件 `expectedVersion` 做 CAS。案件转交或结案会删除该案件的旧授权；专用媒体路由每次还会重新检查会话归属、负责人、案件目标、角色/账号状态、过期时间，以及授权人未举报该目标。每次显式授权或续期写审计，后续 GET、HEAD 和单段 Range 请求只复用授权。授权只适用于 CMS 专用媒体路由，不解锁封面，也不绕过技术验证。

## 讨论与投票

顶层讨论通过 `title` 表达主题，回复通过自引用 `parent_id` 形成树。历史讨论可以没有标题，界面从正文生成兼容标题；新界面要求顶层主题填写标题。数据库保留完整逻辑深度，客户端最多显示五级缩进，避免手机可用宽度被耗尽。

视频价值评价和讨论认同/反对分别存入 `video_votes`、`discussion_votes`，从而保留真实外键。联合主键保证一个账号对一个目标最多一票；视频值为 `1 | 2 | 3`（高/中/低收获），讨论值仍为 `1 | -1`，取消都会删除记录。公开视频目录只使用经过 Beta 平滑和参与度校正的聚合价值，不公开个人选择。

讨论作者可以修改标题与正文，每次实际变化累计 `edit_count` 并记录 `edited_at`。没有回复的讨论可直接删除；已有回复时只擦除作者、标题、正文和票数并留下墓碑。父级外键使用 `ON DELETE RESTRICT`，任何代码路径都不得通过删除父节点级联清除其他用户的回复。治理隐藏显示“正在审核”占位，治理移除显示规则墓碑，二者都保留回复树和仅供 CMS 复核的原正文；CMS 不能恢复作者主动删除的墓碑。

## 账号、内容生命周期与通知

- 用户名是稳定公开地址的一部分，不可修改；显示名称、简介和头像可修改。公开作者主页只列出验证通过、公开、未撤回且未被移除的稿件。
- 撤回是可逆的作者操作：媒体继续保存，但目录、搜索、公开主页和非作者直接访问全部关闭。重新发布只允许验证通过的媒体。
- 永久删除必须发生在撤回之后。删除任务与元数据墓碑在同一数据库事务内持久化，Web 应用立即尝试删文件，验证器对失败任务退避重试。视频、封面和旧头像失去引用后都不得只依赖单次 `unlink`。
- `APPEAL_WINDOW_DAYS` 同时是配置化的治理证据保留窗口。目标仍被隐藏/移除、存在未结案件或申诉，或可申诉的隐藏/移除动作尚在窗口内且其申诉未结束时，视频不得删除，讨论不得编辑或删除。账号注销的内容清理也复用这组保护。
- 只有删除前验证通过、真正公开且审核可见的稿件，原链接才展示停止新增回复的讨论档案。私密、隐藏、待验证或未通过验证的稿件在删除后仍统一返回 404。
- 删除账号会撤销全部会话并移除头像、简介、偏好、通知和账号投票。作者可以分别选择清理稿件和讨论；未选择的内容继续存在但不再关联公开身份。作品 `creator` 是许可证署名而非发布账号，保留稿件时必须保留原值。用户名继续保留占用，避免冒名复用；最后一名有效管理员不能通过这条自助路径注销。
- `suspended` 账号仍可验证密码建立受限会话，只能浏览公开内容、查看本人举报和决定、申诉、修改密码与退出；上传、投票、讨论、资料修改和 CMS 均由服务端拒绝。`disabled` 不能登录，CMS V1 不提供禁用动作。
- 管理员不能暂停或降级自己，也不能暂停、降级或注销最后一名有效管理员。暂停立即撤销目标账号现有会话；角色和状态在请求时从数据库读取，旧 Cookie 不保留已经撤销的后台能力。
- 回复通知逐条保存；删除回复时同步删除它产生的通知，避免匿名墓碑仍泄露原作者。视频只有“高收获”评价生成聚合通知，中/低评价不提醒作者；同一未读窗口内每个账号只计一次当前状态，取消或改票不会刷高计数，公开响应不含评价者身份。通知偏好关闭后不生成该类新记录。
- 当前轮询只服务于打开的页面。浏览器系统通知要求 HTTPS 安全上下文和明确授权；关闭页面后的 Service Worker/Web Push 不属于当前架构。

## 排序与隐私

`/algorithm` 必须描述当前代码，而不是营销承诺。当前公开目录由 `src/ranking.js` 的 `RANKING_VERSION = 1` 排序：首页、搜索、分类和标签使用“价值热度”，把三档价值评价、讨论主题/回复/深度与受上限约束的时间衰减合成；`/featured` 使用不随时间衰减的典范分。周期性复兴只从质量门槛以上的候选中确定性选择，并限制同一作者名额和长视频成本。精确公式、参数、未使用的数据与离线不变量见 [`algorithm.md`](algorithm.md)，页面直接从同一代码模块渲染，避免文档漂移。

当前没有个性化推荐，也不采集或存储观看序列、播放量和停留时长。CMS V1 不提供算法调参页面，治理决定也不作为隐藏的排序惩罚；不可公开内容先由公开查询边界排除。只有出现第二种可发布算法后，才实现“算法版本—离线校验—预览—发布—公开说明—回滚”的完整链路。未来若加入个性化，仍应本地优先，并显式标注、可关闭且不污染全局透明排序。

## 封面生命周期

封面文件保存在 `data/covers`，数据库记录随机存储名、MIME 和来源 `uploaded/generated`。用户封面真实解码、去元数据并统一为 WebP；自动封面仍是 JPEG。只有媒体达到公开技术状态且内容状态允许公开时，封面路由才会响应。媒体被验证器确定拒绝时，已上传封面也会删除；进程中断产生的未跟踪封面、头像和规范化临时文件由验证器的孤儿清理任务回收。

## 任务、备份与恢复

CMS 任务页只能把 `validation_failed` 安全重置为 `pending`，并同时用页面读取的 `validated_at` 与 `validation_started_at` 作 CAS；另一类动作只能让失败文件删除任务立即进入既有队列的下一次重试。只有 validator 能写入 `ready`；只有原删除队列消费者执行物理删除。审核员可在首页看到验证失败视频的必要内容摘要，删除队列则只暴露匿名失败总数；完整 `/cms/tasks`、删除目标/错误和两类重试均只限管理员。

备份和恢复必须复制整个 `data` 目录，而不是只复制 SQLite 或 `data/videos`。当前整体 schema 为 v7：v5 引入 CMS，v6 引入媒体兼容度，v7 引入三档视频价值评价。升级前应停止应用和 validator 并制作一致备份；程序不自动降级，回滚旧代码必须恢复升级前备份，不能只修改 `PRAGMA user_version`。新安装默认使用 `synopt.sqlite`；旧部署可在 `.env` 保留 `DATABASE_PATH=./data/gongying.sqlite`，Compose 会把同一值传给 app 与 validator，防止重建时误启空库。
