# 同见平台架构与维护边界

本文记录已经落地的产品约束和数据边界，避免未来加入管理后台、排序或推荐时破坏现有语义。当前仍是实验性 MVP，不包含 CMS 页面或运营流程。

## 长视频产品约束

- 同见始终以横屏、长视频为主要内容形态，不设计竖屏短视频的沉浸式连续滑动信息流。
- 首页卡片、播放器和封面统一使用 16:9 展示区域；非 16:9 视频在播放器中保持原比例，不裁切原始画面。
- 自定义封面必须严格为 16:9，尺寸在 1280×720 至 3840×2160 之间，只接受 JPEG、PNG 或 WebP，且不得超过 5 MiB。服务端必须真实解码、去除元数据并规范化为 WebP，不得只信任文件头。
- 没有自定义封面时，独立验证器在完整媒体验证通过后读取第一帧，按比例缩放并补边为 1280×720 JPEG。封面提取不是视频转码，不改变原媒体。

## 页面与发现

- `/` 和 `/search`：公开视频目录与搜索。
- `/categories`、`/categories/:slug`：平台维护的多级分类。
- `/tags`、`/tags/:slug`：发布者添加的标签。
- `/videos/:id`：播放、作品信息、双向评价和树状讨论。
- `/about`：平台宗旨与实验边界。
- `/algorithm`：当前实际运行的排序、使用的数据和未使用的数据。

当前搜索匹配标题、创作者署名、作品描述和标签。数据量仍很小时使用参数化 SQLite 查询；需要扩展到全文索引时，应保持相同的公开查询语义并增加迁移，而不是改变 URL。

## 技术状态与内容管理状态必须分离

`videos.validation_status` 只描述媒体管线状态：等待、验证中、通过、有警告、内容拒绝或验证服务失败。验证器只能修改这组状态以及探测结果、摘要和自动封面。`validation_started_at` 同时作为可续租的任务版本；自动封面、完成、拒绝和失败写入都做版本 CAS，因失联而被重领的旧 worker 无权提交结果或安排文件删除。

为未来 CMS 预留的内容状态是：

- `videos.visibility`：`public`、`unlisted`、`private`。
- `videos.moderation_status`：`visible`、`hidden`、`removed`。
- `users.role`：`member`、`moderator`、`administrator`。
- `users.status`：`active`、`suspended`、`disabled`。
- `categories.is_active`、父分类与排序字段由管理能力维护。

未来 CMS 不应把“审核隐藏”伪装成“媒体损坏”，也不应允许管理页面直接把未通过验证的媒体标记为可播放。后台写操作还需要单独加入权限中间件、操作审计、原因、申诉和软删除流程；仅有角色字段不等于已经安全地实现后台。

分类使用稳定 slug 作为公开 URL，显示名称可以由 CMS 修改。视频选择一个主分类；标签使用多对多关系，单个视频最多 8 个。分类由平台维护，标签允许发布者创建并在写入前规范化、去重。

## 讨论与投票

顶层讨论通过 `title` 表达主题，回复通过自引用 `parent_id` 形成树。历史讨论可以没有标题，界面从正文生成兼容标题；新界面要求顶层主题填写标题。数据库保留完整逻辑深度，客户端最多显示五级缩进，避免手机可用宽度被耗尽。

视频票和讨论票分别存入 `video_votes`、`discussion_votes`，从而保留真实外键。联合主键保证一个账号对一个目标最多一票，值只能是 `1` 或 `-1`；取消投票会删除记录。

讨论作者可以修改标题与正文，每次实际变化累计 `edit_count` 并记录 `edited_at`。没有回复的讨论可直接删除；已有回复时只擦除作者、标题、正文和票数并留下墓碑。父级外键使用 `ON DELETE RESTRICT`，任何代码路径都不得通过删除父节点级联清除其他用户的回复。

## 账号、内容生命周期与通知

- 用户名是稳定公开地址的一部分，不可修改；显示名称、简介和头像可修改。公开作者主页只列出验证通过、公开、未撤回且未被移除的稿件。
- 撤回是可逆的作者操作：媒体继续保存，但目录、搜索、公开主页和非作者直接访问全部关闭。重新发布只允许验证通过的媒体。
- 永久删除必须发生在撤回之后。删除任务与元数据墓碑在同一数据库事务内持久化，Web 应用立即尝试删文件，验证器对失败任务退避重试。视频、封面和旧头像失去引用后都不得只依赖单次 `unlink`。
- 只有删除前验证通过、真正公开且审核可见的稿件，原链接才展示停止新增回复的讨论档案。私密、隐藏、待验证或未通过验证的稿件在删除后仍统一返回 404。
- 删除账号会撤销全部会话并移除头像、简介、偏好、通知和账号投票。作者可以分别选择清理稿件和讨论；未选择的内容继续存在但不再关联公开身份。作品 `creator` 是许可证署名而非发布账号，保留稿件时必须保留原值。用户名继续保留占用，避免冒名复用。
- 回复通知逐条保存；删除回复时同步删除它产生的通知，避免匿名墓碑仍泄露原作者。稿件认同与反对按“接收者、作品、方向、未读状态”聚合，同一未读窗口内每个投票账号只计一次当前净方向，且公开响应不含投票者身份。通知偏好关闭后不生成该类新记录。
- 当前轮询只服务于打开的页面。浏览器系统通知要求 HTTPS 安全上下文和明确授权；关闭页面后的 Service Worker/Web Push 不属于当前架构。

## 排序与隐私

`/algorithm` 必须描述当前代码，而不是营销承诺。当前唯一生效的目录排序为：

```sql
ORDER BY created_at DESC, id DESC
```

当前没有个性化推荐，也不存储用于推荐的观看序列。未来若加入个性化，推荐采用本地优先：服务端返回公开候选集，浏览器使用本地分类/标签聚合偏好重新排序；账号同步仅保存用户主动关注、屏蔽的标签，或经明确同意同步的聚合向量。所有公式、参数、输入数据、版本和变更时间必须公开。

## 封面生命周期

封面文件保存在 `data/covers`，数据库记录随机存储名、MIME 和来源 `uploaded/generated`。用户封面真实解码、去元数据并统一为 WebP；自动封面仍是 JPEG。只有媒体达到公开技术状态且内容状态允许公开时，封面路由才会响应。媒体被验证器确定拒绝时，已上传封面也会删除；进程中断产生的未跟踪封面、头像和规范化临时文件由验证器的孤儿清理任务回收。

备份和恢复必须复制整个 `data` 目录，而不是只复制 SQLite 或 `data/videos`。
